How it works

A sealed room for reading contracts

A vendor who has delivered work under the same contract for years quietly stops collecting everything it entitles them to — an escalation never invoked, overage work never billed, a discount still running long after it expired. Finding that means reading contracts the client considers confidential, so the analysis moves in instead: a self-contained demo that reads, transcribes, and audits them with a model running inside the client’s network. The workspace has no internet route, and its model relay exposes inference rather than Ollama’s management API.

Three pictures. The first shows the walls; the second shows what happens to a contract inside them; the third shows how the demo on a laptop maps onto the real deployment.

1. The walls

Every contract is read inside a container on a Docker internal network — one with no default route and firewall rules that drop traffic to other networks. The verified single-workspace demo has exactly two service neighbours on the same box. The model neighbour accepts only model listing and chat completions.

Network

Workspaces are attached to the internal network and nothing else. In a client install the server’s own egress is denied too, as a second fence.

Image

Editor, Python, and every dependency are built into the workspace image from a pinned lockfile. Nothing is downloaded at runtime, so nothing needs a route out.

Proof

A script runs twenty-three checks against a live workspace — topology, container hardening, five internet targets, public DNS, allowed services, blocked model management, and build hygiene. It exits non-zero on any miss.

2. What happens to a contract

The model does what it’s good at — reading scanned pages and spotting the clause where money leaks — and is kept away from what it’s bad at. Discovery does no math; a separate structured pass proposes a formula for one representative month. Code checks cash-flow direction and numeric provenance, handles unambiguous explicit averages and annual-only cadence deterministically, evaluates a bounded arithmetic tree, multiplies the result by twelve, and prints the working beside the result.

3. The demo and the real thing

The laptop demo shows the workspace boundary that a client install can preserve. On a laptop the model and control plane run natively beside Docker — that’s where the GPU is — so two single-port relays stand in for the neighbours. A production server can place the model and control plane directly on private networks, but it also needs TLS, identity, wildcard app subdomains with path apps disabled, private mirrors, a managed database, per-tenant isolation where required, and host-level egress controls.

What a finding looks like

Two findings planted in the synthetic sample contracts — one an expired discount still being given away, the other work delivered but never invoiced. A narrow model pass proposes a monthly formula; code verifies its inputs, uses direct evidence where the rate and average are unambiguous, computes one month, and multiplies by twelve.

FindingWhereThe mathPer year
Discount never reverted. A five-percent new-facility discount was correct for its first twelve months, then should have ended. Invoices two years later still reflect it. §5.2; Exhibit B 840,000 × 5 ÷ 100 ÷ 12 × 12 $42,000
Seat overage never billed. The contract allows billing for active seats beyond the 250 committed. Usage has exceeded that for three straight months with no overage line on any invoice. §2.4; Exhibit B 110 × 11 × 12 $14,520

Sample contracts are synthetic and watermarked as such. Findings are candidates for human review, not legal or accounting advice. Model: Qwen3-VL-8B (Apache-2.0), served by Ollama in this laptop demo. Platform: self-hosted Coder, whose air-gapped deployment guide covers the additional server, registry, provider, STUN, telemetry, and update-check controls required for a fully offline client installation.
