How it works

A sealed room for reading contracts

A vendor who has delivered work under the same contract for years quietly stops collecting everything it entitles them to — an escalation never invoked, overage work never billed, a discount still running long after it expired. Finding that means reading contracts the client considers confidential, so the analysis moves in instead: a self-contained appliance that reads, transcribes, and audits them with a model running inside the client’s network — and is physically unable to send anything out.

Three pictures. The first shows the walls; the second shows what happens to a contract inside them; the third shows how the demo on a laptop maps onto the real deployment.

1. The walls

Every contract is read inside a container on a Docker internal network — one with no address translation and no default route. The container can reach exactly two neighbours, both on the same box. That isn’t a rule someone wrote; there is simply no path out.

Network

Workspaces are attached to the internal network and nothing else. In a client install the server’s own egress is denied too, as a second fence.

Image

Editor, Python, and every dependency are built into the workspace image from a pinned lockfile. Nothing is downloaded at runtime, so nothing needs a route out.

Proof

A script runs fourteen checks against a live workspace — five internet targets and public DNS must fail, the two neighbours must answer. It exits non-zero on any miss.

2. What happens to a contract

The model does what it’s good at — reading scanned pages and spotting the clause where money leaks — and is kept away from what it’s bad at. It never states a dollar figure. It writes down the arithmetic using numbers from the contract, and ordinary code computes the result and prints the working beside it.

3. The demo and the real thing

The laptop demo and a client install run the same workspace, the same template, and the same sealed network. The one difference: on a laptop the model and control plane run natively beside Docker — that’s where the GPU is — so two single-port relays stand in for the neighbours. On a server the neighbours are just containers on the same internal network — no relay, no host hop.

What a finding looks like

Two real findings from the sample contracts, produced inside the sealed workspace — one an expired discount still being given away, the other work delivered but never invoiced. The figure is computed from the formula; the formula is built from numbers the model quoted from the contract, scaled to a full year where the evidence covers less than one.
